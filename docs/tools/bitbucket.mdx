MCP Atlassian provides tools for **Bitbucket Data Center** (self-hosted),
authenticated with OAuth 2.0. See [Bitbucket Data Center setup](/docs/authentication) for
configuration and the [OAuth validation runbook](/docs/guides/bitbucket-oauth-validation).

Bitbucket tools live in **opt-in** toolsets (off by default). Most are read-only; the
pull-request **write** tools additionally honour
[`READ_ONLY_MODE`](/docs/tools-reference#read-only-mode). Enable a toolset explicitly:

```bash
# Enable a Bitbucket toolset (or several, comma-separated)
TOOLSETS=default,bitbucket_pull_requests
# ...or everything
TOOLSETS=all
```

| Toolset | Tools |
| --- | --- |
| `bitbucket_projects` | `bitbucket_list_projects` |
| `bitbucket_repositories` | `bitbucket_list_repositories` |
| `bitbucket_pull_requests` | `bitbucket_list_pull_requests`, `bitbucket_get_pull_request`, `bitbucket_get_pull_request_diff`, `bitbucket_get_pull_request_activities`, `bitbucket_get_pull_request_comments`, `bitbucket_add_comment` (write) |

## Pagination & completeness

List tools page through Bitbucket Data Center and return, alongside the results, three
flags: `count` (items returned), `is_last_page`, and **`truncated`**. `truncated` is the
authoritative completeness signal — when it is `true`, more items exist than were
returned; raise `limit` (when `is_last_page` is `true`) or narrow the query, and do not
treat the list as exhaustive.

## Projects

### `bitbucket_list_projects`

Lists Bitbucket Data Center projects visible to the authenticated user.

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `limit` | int | `25` | Max projects to return (1–1000). |

If `BITBUCKET_PROJECTS_FILTER` is configured, the result is restricted to those project
keys (case-insensitive). A `truncated` *empty* result under a filter means the scan did
not reach the matching project, not that none exists.

## Repositories

### `bitbucket_list_repositories`

Lists repositories in a project.

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `project_key` | str | — | Project key (e.g. `PROJ`). Use `bitbucket_list_projects` to discover keys. |
| `limit` | int | `25` | Max repositories to return (1–1000). |

## Pull requests

### `bitbucket_list_pull_requests`

Lists pull requests in a repository.

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `project_key` | str | — | Project key. |
| `repository_slug` | str | — | Repository slug (e.g. `my-repo`). Use `bitbucket_list_repositories` to discover slugs. |
| `state` | str | `OPEN` | `OPEN`, `DECLINED`, `MERGED`, or `ALL`. |
| `direction` | str | `INCOMING` | `INCOMING` or `OUTGOING`. |
| `at` | str | — | Optional fully-qualified branch ref (e.g. `refs/heads/main`). |
| `order` | str | `NEWEST` | `NEWEST` or `OLDEST`. |
| `limit` | int | `25` | Max pull requests to return (1–100). |

### `bitbucket_get_pull_request`

Gets one pull request's metadata (title/state, source/target refs, reviewer and approval
state).

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `project_key` | str | — | Project key. |
| `repository_slug` | str | — | Repository slug. |
| `pull_request_id` | int | — | Pull-request id (positive integer). |

### `bitbucket_get_pull_request_diff`

Returns the pull request's diff as a **structured hunk model** (files → hunks → segments →
lines), not raw unified-diff text. The diff is bounded for token control.

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `project_key` | str | — | Project key. |
| `repository_slug` | str | — | Repository slug. |
| `pull_request_id` | int | — | Pull-request id. |
| `max_lines_per_file` | int | `500` | Per-file line cap (1–5000). Over-budget files are flagged `line_truncated` with the dropped count in `omitted_lines`. |
| `max_files` | int | `100` | Max changed files (1–1000). Excess files are omitted; `total_files` reports the full count and `truncated` is set. |

Server-side truncation flags from Bitbucket (e.g. a binary or server-truncated file) are
preserved separately from these client-side budgets.

### `bitbucket_get_pull_request_activities`

The activity timeline — comments, approvals, merges, rescopes, and other actions in
chronological order.

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `project_key` | str | — | Project key. |
| `repository_slug` | str | — | Repository slug. |
| `pull_request_id` | int | — | Pull-request id. |
| `limit` | int | `25` | Max activity entries to return (1–200). |

### `bitbucket_get_pull_request_comments`

A focused view over the timeline — only comment actions, with the comment payload (text,
author, thread state) surfaced. Backed by the same endpoint as the activities tool.

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `project_key` | str | — | Project key. |
| `repository_slug` | str | — | Repository slug. |
| `pull_request_id` | int | — | Pull-request id. |
| `limit` | int | `25` | Max comments to return (1–200). |

### `bitbucket_add_comment` (write)

Adds a comment to a pull request. The comment mode follows which optional parameters are
supplied:

| Inputs | Result |
| --- | --- |
| `text` only | A general pull-request comment. |
| `parent_id` | A reply to that comment (cannot be combined with any anchor parameter). |
| `file_path` | A whole-file comment. |
| `file_path` + `line` + `line_type` | A comment on a specific diff line. |
| `severity="BLOCKER"` | Raises a **task** (a must-resolve item); valid in any mode. |

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `project_key` | str | — | Project key. |
| `repository_slug` | str | — | Repository slug. |
| `pull_request_id` | int | — | Pull-request id. |
| `text` | str | — | Comment text (Markdown); must be non-blank. |
| `parent_id` | int | — | Reply to this comment id. |
| `file_path` | str | — | File to anchor the comment to. |
| `line` | int | — | 1-based diff line to anchor to (requires `file_path` and `line_type`). |
| `line_type` | str | — | `ADDED`, `REMOVED`, or `CONTEXT` (an unchanged nearby line). |
| `file_type` | str | derived | `FROM` (source) or `TO` (destination). Defaults from `line_type` (`REMOVED`→`FROM`, `ADDED`/`CONTEXT`→`TO`). |
| `severity` | str | `NORMAL` | `NORMAL` or `BLOCKER` (a task). |

Line and whole-file anchors land on the pull request's **current effective diff** — the
same diff `bitbucket_get_pull_request_diff` returns — so anchor against the diff you just
read; no commit hashes are required. The tool returns the created comment's `id` and
`version` (the version is the optimistic-lock token a later edit or delete must echo).

<Note>
On Data Center, **commenting requires only `REPO_READ`** — a reviewer who can read a pull
request can comment on it; `REPO_WRITE` is not needed. The tool is still gated by
[`READ_ONLY_MODE`](/docs/tools-reference#read-only-mode): when that is set, the tool is
blocked server-side and no request is made.
</Note>

## A pull-request review pass

```text
bitbucket_list_projects                 → find the project key
bitbucket_list_repositories(project)    → find the repository slug
bitbucket_list_pull_requests(repo)      → find the open PR and its id
bitbucket_get_pull_request(id)          → title, refs, approval state
bitbucket_get_pull_request_diff(id)     → the changes (bounded for token budget)
bitbucket_get_pull_request_comments(id) → existing review discussion
bitbucket_add_comment(id, …)            → leave review feedback (general or on a line)
```

## Errors

Failures return a sanitised JSON error object (`success: false`, `error: "…"`) — never raw
upstream detail. A missing/no-access project, repository, or PR returns a `Not Found:`
error; token rejection returns an `Authentication/Permission Error:`; transport/API issues
return a `Network or API Error:`.

## Writes

Pull-request **commenting** (`bitbucket_add_comment`, above) is the first write tool. Like
every write tool, it is blocked when the server runs with
[`READ_ONLY_MODE`](/docs/tools-reference#read-only-mode) — the call is rejected server-side
before any request is made. Further writes (review status, merge, branch management) are
future work.
