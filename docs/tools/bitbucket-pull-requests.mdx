### List Bitbucket Pull Requests

List pull requests in a Bitbucket Data Center repository.

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `project_key` | `string` | Yes | The Bitbucket project key (e.g. 'PROJ'). Use list_projects to discover available keys. |
| `repository_slug` | `string` | Yes | The repository slug (e.g. 'my-repo'). Use list_repositories to discover available slugs. |
| `state` | `string` | No | Filter by pull-request state: 'OPEN' (default), 'DECLINED', 'MERGED', or 'ALL'. Any other value is rejected. |
| `direction` | `string` | No | Direction relative to the repository: 'INCOMING' (default) or 'OUTGOING'. Any other value is rejected. |
| `at` | `string` | No | Optional fully-qualified branch ref to filter on (e.g. 'refs/heads/main'). |
| `order` | `string` | No | Ordering: 'NEWEST' (default) or 'OLDEST'. Any other value is rejected. |
| `filter_text` | `string` | No | Optional substring match on PR title or description. |
| `draft` | `boolean` | No | Optional filter by draft status. |
| `start` | `integer` | No | Pagination cursor: the offset of the first pull request to return. Use 0 (default) for the first window, then pass the response's 'next_page_start' to fetch the next window. |
| `limit` | `integer` | No | Maximum number of pull requests to return in this window. If more exist than are returned, the response sets 'truncated' to true and 'next_page_start' to the cursor for the next call. |
| `summary` | `boolean` | No | When true, return only each pull request's triage fields (id, title, state, author, and the target repository's project_key and repository_slug) instead of the full record, for scanning a large list to pick one before fetching its full detail. |

### Create Bitbucket Pull Request

Create a pull request (needs REPO_READ on the source and target repositories).

<Note>This is a **write** tool. Disabled when `READ_ONLY_MODE=true`.</Note>

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `project_key` | `string` | Yes | The target Bitbucket project key (e.g. 'PROJ'). |
| `repository_slug` | `string` | Yes | The target repository slug (e.g. 'my-repo'). |
| `title` | `string` | Yes | The pull-request title. One non-blank line of at most 255 characters. |
| `from_ref` | `string` | Yes | The source branch or tag. A bare name ('feature/x') is sent as 'refs/heads/feature/x'. A value starting with 'refs/' (for example 'refs/tags/v1.2') is sent as given. |
| `to_ref` | `string` | Yes | The target branch. A bare name ('main') is sent as 'refs/heads/main'. A 'refs/heads/...' value is sent as given. Tags are not valid targets. |
| `description` | `string` | No | The pull-request description (Markdown) of at most 32768 characters. |
| `draft` | `boolean` | No | Create the pull request as a draft. Omit to leave the server default (not a draft). Needs a Data Center version with draft pull requests. The flag is confirmed against the response. |
| `reviewers` | `array` | No | User names to add as reviewers (the 'name' field of get_current_user, not the display name). Repeated names are sent once. A name the server cannot resolve fails the whole request with a 409. |
| `from_repo` | `string` | No | The repository holding 'from_ref' when it is not the target repository, as 'PROJECT/slug'. Must be a fork in the same hierarchy as the target. Omit for a same-repository pull request. |

### Update Bitbucket Pull Request

Update pull-request metadata (needs REPO_WRITE, or REPO_READ as the author).

<Note>This is a **write** tool. Disabled when `READ_ONLY_MODE=true`.</Note>

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `project_key` | `string` | Yes | The Bitbucket project key (e.g. 'PROJ'). |
| `repository_slug` | `string` | Yes | The repository slug (e.g. 'my-repo'). |
| `pull_request_id` | `integer` | Yes | The pull-request id (a positive integer). |
| `version` | `integer` | Yes | The pull request's current version, read from get_pull_request immediately before updating. A 409 means the pull request changed since you read it. Re-read and retry. |
| `title` | `string` | No | A new title: one non-blank line of at most 255 characters. Omit to keep the current one. |
| `description` | `string` | No | A new description (Markdown) of at most 32768 characters; it replaces the whole text, and an empty string clears it. Omit to keep the current one. |
| `draft` | `boolean` | No | Set (true) or clear (false) the draft flag. Omit to keep the current one. Needs a Data Center version with draft pull requests. The flag is confirmed against the response. |
| `to_ref` | `string` | No | A new target branch. A bare name ('main') is sent as 'refs/heads/main'. A 'refs/heads/...' value is sent as given. Tags are not valid targets. Omit to keep the current one. |
| `reviewers` | `array` | No | The complete new reviewer list as user names (the 'name' field of get_current_user). It replaces the current list, so include the reviewers to keep. An empty list removes every reviewer. Omit to keep the current list. A name the server cannot resolve fails the whole request with a 409. |

<Note>
Bitbucket allows this update for the pull request's author with `REPO_READ`, and for anyone else only with `REPO_WRITE`. The documented OAuth setup grants `REPO_READ`, so updating another author's pull request needs `BITBUCKET_OAUTH_SCOPE=REPO_WRITE` (or a token issued with it). That scope applies to every token the server issues and also enables merge, decline, and comment deletion for all users. Every optional field keeps its current value when omitted, at least one must be given, and an empty `description` clears it. `reviewers` is replaced as a whole: pass the complete list to keep, add, or drop reviewers, and pass an empty list to remove them all. Omitting it leaves the list unchanged. The author and the participants cannot be changed here. The tool does not fetch `version`: read it with `bitbucket_get_pull_request` first, and a 409 means it is stale. The response is checked against the submitted fields, except a non-empty reviewer list, because Bitbucket can omit the author. Its `version` is expected to be the sent one plus one. A body that differs is reported as an unconfirmed write.
</Note>

### Add Bitbucket Pull Request Comment

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `project_key` | `string` | Yes | The Bitbucket project key (e.g. 'PROJ'). |
| `repository_slug` | `string` | Yes | The repository slug (e.g. 'my-repo'). |

| `line` | `integer` | No | Anchor to this 1-based line in the diff. Requires 'file_path' and 'line_type'. The comment lands on the PR's current effective diff (the same diff get_pull_request_diff returns). |
| `line_type` | `string` | No | Diff line kind for a line comment: 'ADDED', 'REMOVED', or 'CONTEXT' (an unchanged line near the change). Required with 'line'. |
| `file_type` | `string` | No | Diff side a line comment attaches to: 'FROM' (source) or 'TO' (destination). Defaults from 'line_type' (REMOVED→FROM, ADDED/CONTEXT→TO) when omitted. |
| `severity` | `string` | No | 'NORMAL' (default) for a comment, or 'BLOCKER' to raise a task (a must-resolve item), valid in any comment mode. |

### Resolve Bitbucket Pull Request Task

Resolve or reopen a Bitbucket Data Center pull-request task (needs REPO_READ).

<Note>This is a **write** tool. Disabled when `READ_ONLY_MODE=true`.</Note>

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `project_key` | `string` | Yes | The Bitbucket project key (e.g. 'PROJ'). |
| `repository_slug` | `string` | Yes | The repository slug (e.g. 'my-repo'). |
| `pull_request_id` | `integer` | Yes | The pull-request id (a positive integer). |
| `comment_id` | `integer` | Yes | The id of the task comment (a comment with severity BLOCKER). |
| `version` | `integer` | Yes | The comment's current version, from add_pull_request_comment or get_pull_request_comments. A 409 means the comment changed since you read it. Re-fetch its version and retry. |
| `state` | `string` | No | The task state to set: 'RESOLVED' (default) or 'OPEN' to reopen. Any other value is rejected. |

<Note>
A task is a pull-request comment whose `severity` is `BLOCKER`. Bitbucket lists open tasks as a must-do checklist and can block merging on them. Its `state` (`OPEN` or `RESOLVED`) is separate from the comment thread's resolved flag: `bitbucket_resolve_pull_request_comment` resolves the thread, this tool resolves the task. Both are `PUT` updates on the same comment endpoint with the comment's current `version`. The endpoint needs `REPO_READ` on the repository, and Bitbucket lets the comment author, the pull-request author, or a repository admin change the task state. Comments that are not tasks (`severity: NORMAL`) have no task state. If the server accepts the request but leaves `state` unchanged, the tool reports the write as unconfirmed.
</Note>
