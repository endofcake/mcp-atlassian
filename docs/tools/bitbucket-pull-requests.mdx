### List Bitbucket Pull Requests

List pull requests in a Bitbucket Data Center repository.

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `project_key` | `string` | Yes | The Bitbucket project key (e.g. 'PROJ'). Use list_projects to discover available keys. |
| `repository_slug` | `string` | Yes | The repository slug (e.g. 'my-repo'). Use list_repositories to discover available slugs. |
| `state` | `string` | No | Filter by pull-request state: 'OPEN' (default), 'DECLINED', 'MERGED', or 'ALL'. Any other value is rejected. |
| `direction` | `string` | No | Direction relative to the repository: 'INCOMING' (default) or 'OUTGOING'. Any other value is rejected. |
| `at` | `string` | No | Optional fully-qualified branch ref to filter on (e.g. 'refs/heads/main'). |
| `order` | `string` | No | Ordering: 'NEWEST' (default) or 'OLDEST'. Any other value is rejected. |
| `filter_text` | `string` | No | Optional substring match on PR title or description. |
| `draft` | `boolean` | No | Optional filter by draft status. |
| `start` | `integer` | No | Pagination cursor: the offset of the first pull request to return. Use 0 (default) for the first window, then pass the response's 'next_page_start' to fetch the next window. |
| `limit` | `integer` | No | Maximum number of pull requests to return in this window. If more exist than are returned, the response sets 'truncated' to true and 'next_page_start' to the cursor for the next call. |
| `summary` | `boolean` | No | When true, return only each pull request's triage fields (id, title, state, author, and the target repository's project_key and repository_slug) instead of the full record, for scanning a large list to pick one before fetching its full detail. |

### List Bitbucket Pull Requests for a User

List the pull requests a user is involved in, across all repositories.

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `user` | `string` | No | Bitbucket username whose pull requests to list. Defaults to the authenticated user (the identity behind the server's Bitbucket credentials), so a call without it answers 'my pull requests'. Results are still limited to what the caller may see. |
| `role` | `string` | No | Filter by the user's role on each pull request: 'REVIEWER', 'AUTHOR', or 'PARTICIPANT'. Omit for any role. Any other value is rejected. |
| `participant_status` | `array` | No | Filter by the user's participant status: any of 'UNAPPROVED', 'NEEDS_WORK', 'APPROVED'. Omit for any status. Any other value is rejected. |
| `state` | `string` | No | Filter by pull-request state: 'OPEN', 'DECLINED', or 'MERGED'. Omit for any state. Any other value is rejected. |
| `order` | `string` | No | Ordering: 'NEWEST' (default), 'OLDEST', 'DRAFT_STATUS', 'PARTICIPANT_STATUS', or 'CLOSED_DATE'. Any other value is rejected. |
| `closed_since` | `integer` | No | Only pull requests closed within the last N seconds (e.g. 86400 for the previous 24 hours). Omit for no closed-date window. |
| `start` | `integer` | No | Pagination cursor: the offset of the first pull request to return. Use 0 (default) for the first window, then pass the response's 'next_page_start' to fetch the next window. |
| `limit` | `integer` | No | Maximum number of pull requests to return in this window. If more exist than are returned, the response sets 'truncated' to true and 'next_page_start' to the cursor for the next call. |
| `summary` | `boolean` | No | When true, return only each pull request's triage fields (id, title, state, author, and the target repository's project_key and repository_slug) instead of the full record, for scanning a large list to pick one before fetching its full detail. |

### Get Bitbucket Pull Request Diff

Get a Bitbucket Data Center pull request's structured diff.

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `project_key` | `string` | Yes | The Bitbucket project key (e.g. 'PROJ'). |
| `repository_slug` | `string` | Yes | The repository slug (e.g. 'my-repo'). |
| `pull_request_id` | `integer` | Yes | The pull-request id (a positive integer). |
| `max_lines_per_file` | `integer` | No | Maximum diff lines to return per file (token control). Files exceeding this are truncated; the response flags the file with 'line_truncated' and counts the dropped lines in 'omitted_lines'. |
| `max_files` | `integer` | No | Maximum number of changed files to return (token control). If the diff holds more files than this, the response returns the first 'max_files' and sets 'truncated' to true. 'total_files' counts the files in the diff Bitbucket returned, which a 'path' filter or Bitbucket's own limits may already have reduced. |
| `context_lines` | `integer` | No | Number of unchanged context lines to include around each change, applied by the server before download. Omit for the server default (10). Lower it to shrink a large diff. |
| `path` | `string` | No | Diff a single file at this path instead of the whole pull request. Use bitbucket_get_pull_request_changes to list the paths. '.'/'..' and traversal paths are rejected. |
| `src_path` | `string` | No | The file's previous path when it was moved, copied, or renamed (the 'src_path' of its changed-file entry). Only valid together with 'path'. |

### Add Bitbucket Pull Request Comment

Add a comment to a Bitbucket Data Center pull request.

<Note>This is a **write** tool. Disabled when `READ_ONLY_MODE=true`.</Note>

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `project_key` | `string` | Yes | The Bitbucket project key (e.g. 'PROJ'). |
| `repository_slug` | `string` | Yes | The repository slug (e.g. 'my-repo'). |
| `pull_request_id` | `integer` | Yes | The pull-request id (a positive integer). |
| `text` | `string` | Yes | The comment text (Markdown). Must be non-blank. |
| `parent_id` | `integer` | No | Reply to this comment id. A reply inherits the parent thread's anchor, so it cannot be combined with any file/line parameter. |
| `file_path` | `string` | No | Anchor the comment to this file path (a whole-file comment, or a line comment when 'line' is also given). Omit for a general pull-request comment. |
| `line` | `integer` | No | Anchor to this 1-based line in the diff. Requires 'file_path' and 'line_type'. The comment lands on the PR's current effective diff (the same diff get_pull_request_diff returns). |
| `line_type` | `string` | No | Diff line kind for a line comment: 'ADDED', 'REMOVED', or 'CONTEXT' (an unchanged line near the change). Required with 'line'. |
| `file_type` | `string` | No | Diff side a line comment attaches to: 'FROM' (source) or 'TO' (destination). Defaults from 'line_type' (REMOVED→FROM, ADDED/CONTEXT→TO) when omitted. |
| `severity` | `string` | No | 'NORMAL' (default) for a comment, or 'BLOCKER' to raise a task (a must-resolve item), valid in any comment mode. |
